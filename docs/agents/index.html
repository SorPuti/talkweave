1. Preparar e executar a referência Python

Extraia o ZIP numa pasta nova, leia README.md e AGENTS.md e execute na raiz:

python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python run.py
# Terminal interativo: python run.py --ui
# Retomar: python run.py --resume

2. Conferir cada etapa

  1. 01-baselinepython src/baseline.pyEvidência: baseline.npz
  2. 02-fixturepython src/fixture.pyEvidência: data/train.jsonl, data/validation.jsonl
  3. 03-testspython -m pytest -qEvidência: log e código de saída
  4. 04-codecpython src/train.py codec --manifest data/train.jsonl --validation data/validation.jsonl --steps 100Evidência: runs/codec.pt
  5. 05-reconstructionpython src/reconstruct.py --input data/validation-user.wav --output reconstructed.wavEvidência: reconstructed.wav
  6. 06-duplexpython src/train.py duplex --manifest data/train.jsonl --validation data/validation.jsonl --steps 100Evidência: runs/duplex.pt
  7. 07-generationpython src/infer.py --input data/validation-user.wav --output reply.wavEvidência: reply.wav, reply.wav.json
  8. 08-evaluationpython src/evaluate.py --manifest data/validation.jsonl --report reply.wav.jsonEvidência: log e código de saída

3. Entregar o registro

O runner salva work/talkweave-demo/REPORT.md, report.json e logs/. Ele interrompe na falha e só retoma etapas com evidências intactas. O agente complementa a análise de qualidade usando docs/report.md.

Uma organização pequena e explícita

run.py        → execução guiada
src/          → áudio, modelo, protocolo e UI
cfg/          → configurações
data/         → gravações locais
runs/         → pesos e métricas
logs/         → evidências
docs/         → padrões e relatório
tests/        → testes
work/         → experimentos isolados

Funções com docstrings de uma linha em inglês, nomes claros, interfaces tipadas e filas limitadas. A interface é observadora do streaming, fora da callback de áudio.
